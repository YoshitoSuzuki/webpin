# 開発の記録

## 2026-08-21 — 新規作成

「AI と Web を作るとき、完成品を見てからの細かい修正指示が面倒」という課題から作った。

決めたこと:

- **汎用ツールにする**。特定のサイト専用にせず、ローカルの Web プロジェクトなら何でも対象にする。
  サイトの構成（build.js、translations.js など）はコードに直書きせず、
  ファイルの有無から動的に判断する
- **専用ローカルサーバー方式**。ブックマークレットや Chrome 拡張ではなく、配信時にオーバーレイを
  注入する。リポジトリ内のファイルを一切書き換えないので、本番に混入しない
- **保存先はプロジェクト外**（`~/.cache/webpin/`）。リポジトリが丸ごと
  公開ディレクトリにコピーされる構成だと、中に置くとスクリーンショットまで公開されうる
- **自動で書き換えるのはテキストだけ**。スタイル変更を CSS に自動反映するのは、
  どのファイルのどのルールに書くかが判断を含むためやらない
- **もう一方の言語を機械的に上書きしない**。訳は指摘として残して AI に任せる

作る前に調べてわかったこと:

- 生成された HTML に「自動生成」を示すマーカーが**一切ない**。パス規則で判定するしかない。
  `build.js` の有無だけでは足りず、`template_*.html` の存在まで見る必要がある
- 要素の `textContent` で検索すると、`<br>` や `<strong>` を含む要素がソースに一致しない。
  テキストノード単位で扱う必要がある
- Chrome 136 以降、既定プロファイルでは `--remote-debugging-port` が拒否される。
  専用の `--user-data-dir` が必須
- PHP のページにはそれまでローカルプレビュー手段が無かった。
  `php -S` へのプロキシを入れたのでレイアウト確認はできるようになった（DB には繋がらない）

動作確認した内容（自分のサイト上）:

- 一覧の JSON → 文字を直すと lab.json が変わり `node build.js` で生成 HTML にも反映
- `content.js` → ブラウザ上で段落を書き換えると content.js が変わり、`<br>` は保持
- `translations.js` → 日本語だけ書き換わり、英語は訳し直しの指摘になる
- 掲示板（PHP）→ プロキシ経由で表示できる（DB 未接続で 500、レイアウトのみ）
- CDP による範囲スクリーンショット

## 2026-08-22 — 指摘が一覧に出ない問題を直した

自動で書き換えた分を `status: done` として記録していたため、`webpin notes` が
（未処理だけを出す仕様上）**何も表示しなかった**。ブラウザで文字を消しても直しても、
CLI 側では何も起きていないように見えていた。

- 自動適用した記録は `applied` という別の状態にして、`webpin notes` に `+` 付きで出すようにした。
  `webpin done <id>` を付けるまで一覧に残る
- **文字を全部消す操作は自動適用の対象から外した。** 空文字を書き込むと空の要素が
  レイアウトに残る場合があり、要素ごと消すべきかは判断が要るため、`kind: delete` の
  指摘として AI に渡す

## 2026-08-25 — DB / セッションつきの PHP ページに指摘を付けられるようにした

会員ページはログインと MySQL が前提で、DB が本番サーバーからしか繋がらないため
**手元では動かない**（`php -S` は上がるが DB への接続で止まる）。ローカルで再現する道は無いので、
**本番の応答をそのまま借りて表示する**方式にした（`lib/live.js`）。

```bash
cd ~/projects/my-site
webpin --live https://example.com  # 以後このプロジェクトでは記憶する
webpin --local                     # やめるとき
```

決めたこと:

- **ローカル優先、足りない分だけ本番から借りる。** `.php` に解決されるリクエストと、
  手元に無いファイルだけを中継し、手元にある静的ファイル（CSS/JS/画像）はローカルから返す。
  こうすると本番の HTML を見ながら、CSS の編集結果はその場で確認できる
- **ライブ中は `php -S` を立てない。** PHP は本番が実行するので不要で、
  立てると PHP がリポジトリ内にセッションファイルを書き出して汚れる
- **設定はキャッシュ側に持つ**（`~/.cache/webpin/<...>/config.json`）。
  リポジトリに `.webpin.json` を置くと、構成によっては公開ディレクトリに出てしまう

中継で必要だったこと:

- `Set-Cookie` から `Domain=` と `Secure` を落とす（`SameSite=None` は `Lax` に）。
  やらないと localhost にセッション Cookie が残らず、ログインが維持できない
- `Origin` / `Referer` を本番のものに書き換える（CSRF 判定に引っかからないように）
- `Location` の絶対 URL を localhost に戻す（中継の外に出てしまうため）
- `Accept-Encoding: identity` で要求する（gzip されると HTML にオーバーレイを差し込めない）
- 応答の CSP・HSTS・`X-Frame-Options` は落とす（注入したスクリプトを止めうる／
  localhost に HSTS が残ると面倒）

- **ソースを直しても画面は変わらない**（本番を見ているため）ので、適用したことを
  オーバーレイのトースト（`… を直しました（画面は https://… のままです）`）で知らせるようにした

わかったこと:

- ライブ中のページ操作は**本番への操作そのもの**。旅程表の編集ボタンなどを押せば
  本番の DB が変わる。見るだけのつもりで触らないこと
- ヘッドレス Chrome で撮ろうとすると、オーバーレイの SSE 接続が開いたままなので
  読み込み完了にならず `--screenshot` が返ってこない。確認は普通の Chrome で行う

## 2026-08-25 — スクロールするとピンと入力欄がずれていたのを直した

オーバーレイの `layer` は `position:fixed` の host の中にあるので、**absolute の基準は
ビューポート原点**になる。そこにページ座標（`getBoundingClientRect()` + `scrollY`）を
入れていたため、スクロール量ぶんずれていた。

- **ピン**: スクロールしても画面に貼り付いたまま付いてきた（`r.top` が減るのと `scrollY` が
  増えるのが相殺して、見かけ上その場に留まる）。要素ではなく画面に紐づいて見えていた
- **コメント入力欄**: 開いた瞬間にスクロール量ぶん下に出るので、少し下までスクロールした
  状態だと**画面の外**に出て、何も起きていないように見えていた。
  「範囲を囲んでもコメントの書き方がわからない」の正体はこれ

直し方は座標からスクロール量を外すだけ。あわせて、
入力欄が画面の端で見切れないよう `placePopup()` でビューポート内に収めるようにした。

確認: 800px 下の要素に指摘を付け、600px スクロールした状態で
ピンが要素の左上（`target=208` に対して `pin=198`）に来ることをヘッドレス Chrome で実測。

- ヘッドレスで確認するときは `window.EventSource` をスタブに差し替える。
  オーバーレイの SSE 接続が開いたままだと仮想時間が進まず、タイマーが動かないまま
  DOM がダンプされる（`window.scrollTo` も headless では scroll イベントを出さないので、
  手で `dispatchEvent` する必要がある）

## 2026-09-06 — README を英語で書き直した

GitHub で見つけた人がそのまま導入できるように、README を英語の導入ガイドにした
（それまでは日本語で docs/ へのリンクを並べただけだった）。

- 導入手順を段階ごとに書いた: clone → `bin/webpin` を PATH 上に symlink →
  `webpin --help` で確認。依存が無い（`npm install` 不要）ことと、
  clone 先を動かすと symlink が切れることを明示した
- macOS 前提であることを隠さず書いた。Chrome のパスが直書きで、開けないときの
  フォールバックが `open` のため。他の OS では `--no-open` と、
  スクショ用に `--remote-debugging-port=<port+2>` で自分で Chrome を起動する道を示した
- モード名（注釈 / 文字 / 範囲 / 見た目）とオーバーレイ・CLI の出力が日本語であることを
  「既知の制約」に書いた。読む人が面食らわないようにするため
- `webpin notes --json` を AI への受け渡し口として説明し、そのまま貼れる指示文を載せた
  （`/web-review` スキルは手元の `~/.claude/` にあってリポジトリには無いため）
- 例として載せた出力（`src:` の `テキスト一致`、`適用:` 行）は `bin/webpin` の
  実際の書式に合わせた。docs/ は日本語のまま残し、README から参照する
