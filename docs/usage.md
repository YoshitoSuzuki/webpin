# webpin の使い方

最終更新: 2026-08-25

## 必要なもの

- Node.js（標準ライブラリだけを使う。`npm install` は不要）
- Google Chrome（`/Applications/Google Chrome.app`）— スクリーンショットに使う
- PHP（任意）— `.php` のページをローカルで表示したいときだけ

## 起動

```bash
cd ~/projects/my-site
webpin
```

- URL が表示され、Chrome が開く。**ポートはプロジェクトのパスから決まる**ので、
  何度立ち上げ直しても同じ URL（例: `http://127.0.0.1:51281/`）
- Chrome は `~/.cache/webpin/chrome` という専用プロファイルで開く。
  Chrome 136 以降は既定プロファイルでのリモートデバッグを拒否するため、これは必須
- 止めるのは `Ctrl-C`。一緒に立てた `php -S` も落ちる

オプション:

```bash
webpin ~/projects/other-site                  # ディレクトリを指定する
webpin --port 8080                            # ポートを固定する
webpin --no-open                              # ブラウザを開かない
webpin --live https://example.com             # PHP は本番の応答を借りる（下記）
webpin --local                                # ライブ中継をやめる
```

## DB やログインが要る PHP ページ（ライブ中継）

会員ページや掲示板のように、**ログインと DB が前提の PHP ページ**は
手元では動かないことが多い（DB が本番サーバーからしか繋がらない場合、`php -S` を立てても
DB への接続で止まる）。

このときは本番の応答を借りて表示する:

```bash
cd ~/projects/my-site
webpin --live https://example.com
```

- **一度指定すればそのプロジェクトでは覚える**（`~/.cache/webpin/<...>/config.json`）。
  次からは `webpin` だけでよい。やめるときは `webpin --local`
- 中継するのは **`.php` に解決されるリクエストと、手元に無いファイル**だけ。
  手元にある CSS / JS / 画像はローカルから返すので、**本番の HTML を見ながら
  CSS の修正結果をその場で確認できる**
- **ログインもそのまま通る**。`http://127.0.0.1:<port>/members/` のようなページを開くと
  本番のログイン画面が出るので、いつもの ID とパスワードで入ればセッションが維持される
- 指摘の逆引きは変わらない。ページの URL からリポジトリ内のファイル（`…/members/index.php` など）を
  そのまま引ける

注意:

- **見えているのは本番そのもの。** ボタンを押せば本番の DB が変わる。フォームの送信など、
  書き込む操作をうっかり触らないこと
- **文字を直しても画面は変わらない。** ソース（手元のリポジトリ）は書き換わるが、
  表示しているのは本番の HTML なので、反映はデプロイ後。
  適用できたかどうかは画面右下のトーストと `webpin notes` の `+` で確認する
- 本番の HTML に `https://example.com/...` という絶対 URL のリンクがあると、
  そこをクリックした時点で中継の外（本物のサイト）に出る

## ブラウザでの操作

右下のツールバーでモードを選ぶ。もう一度押すか `Esc` で解除。

### 注釈

要素にカーソルを合わせると枠が出る。クリックして入力欄にコメントを書き、`追加`。
`Cmd+Enter` でも確定する。左上に番号のピンが残る。

### 文字

クリックした**文字（テキストノード）だけ**が編集可能になる。直して `Enter`（`Esc` で取り消し）。

- ソースの該当箇所が1つに決まれば**その場でファイルが書き換わる**。`build.js` のある
  ディレクトリなら自動で再ビルドされ、ページがリロードされる。
  書き換えた内容は `webpin notes` に `+`（適用済み）として残るので、あとから確認できる
- 決まらなければ（同じ文字列が複数ある、短すぎる、タグをまたいでいる等）
  「これをこう直す」という指摘として残り、AI が処理する
- **文字を全部消したときは自動で反映しない。** 「消す」は文字の入れ替えではなく構造の変更で、
  要素ごと消すのか空のまま残すのかは機械的に決められないため、指摘として残して AI に任せる
- `data-i18n` の付いたページ（アプリ紹介ページ）は、**見ている言語のエントリだけ**を直す。
  もう一方の言語は「訳し直す」という指摘として残る（機械的に上書きしない）

### 範囲

`範囲` を押してからドラッグで矩形を描く。**指を離した位置にコメント欄が出る**ので、
書いて `追加`（`Cmd+Enter` でも確定）。矩形の範囲はそのままスクリーンショットとして撮られる。
8px 四方より小さい矩形は無視される（ただのクリックと区別するため）。
画像は `~/.cache/webpin/<...>/shots/` に入り、AI が読む。

### 見た目

要素をクリックすると、文字サイズ・内側の余白・外側の余白・色・背景の入力欄が出る。
入力すると画面に即反映される（プレビュー）。`記録` で変更値を指摘として残し、`戻す` で破棄する。

**CSS への反映は自動ではやらない。** どのファイルのどのルールに書くか、メディアクエリの
中かどうかは機械的に決められないため、AI に任せる。

### 一覧

溜まっている指摘の一覧。`×` で個別に消せる。ボタンの数字は未処理の件数。

## 溜めた指摘を処理する

Claude Code で:

```
/web-review
```

指摘を読み、ソース候補を起点に修正し、build.js を回し、完了マークまで付ける。

CLI から直接見ることもできる:

```bash
webpin notes          # 未処理（*）と適用済み（+）の一覧
webpin notes --json   # 機械向け（候補ファイル・スクショの絶対パス入り）
webpin notes --all    # 完了済み（-）も含める
webpin show 3         # 1件の詳細
webpin done 3 --note "短く言い換えた"
webpin clear          # 完了済みを捨てる
```

**サーバーが起動していなくても読める。**

## ブラウザが開かないとき

**同じプロファイルを掴んでいる Chrome が別にいると、URL がそちらに渡されて窓が出ない。**
webpin は `~/.cache/webpin/chrome` という専用プロファイルで Chrome を起動するが、
Chrome は「そのプロファイルを使っている既存プロセス」を見つけると、新しい窓を作らずに
そのプロセスへ URL を渡す。相手がヘッドレスだったり終了しかけていたりすると、
画面には何も出ないまま終わる。

```bash
ps aux | grep '[G]oogle Chrome' | grep 'cache/webpin/chrome'   # いるか確認
pkill -f 'user-data-dir=/Users/<user>/.cache/webpin/chrome'     # 落とす
```

落としてから `webpin` を叩き直せば開く。サーバー自体は動いているので、
表示されている URL を普通のブラウザに貼っても使える。

## わかっている制約

- **DB やセッションに依存する PHP ページはローカルでは動かない。**
  DB の設定ファイルを gitignore しているプロジェクトでは、ローカルでは 500 になる。
  レイアウトの確認まではできる。ちゃんと見たいときは上の `--live` を使う
- スクリーンショットは webpin が開いた Chrome のタブでしか撮れない。
  別のブラウザで開いた場合は、矩形の座標と範囲内の要素一覧だけが記録される
- 生成物（build.js の出力）に直接書かれた文言で、ソース側に同じ文字列が無いもの
  （build.js のコード内で組み立てている文字列など）は候補ゼロになる。指摘として残るので
  AI が build.js を読んで直す
