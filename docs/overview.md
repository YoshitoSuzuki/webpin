# webpin 概要

最終更新: 2026-08-21

## 何のために作ったか

AI（Claude Code）と一緒に Web ページを作っていると、**完成品をブラウザで見たあとの細かい
直しを言葉で説明し直すのが面倒**だった。「上から3つ目の段落の後半」「Works の見出しの下の
余白」——画面上の場所を毎回文章で特定する必要があり、そのコストが修正のたびにかかる。

さらにビルドスクリプトで生成しているサイトでは、**画面に見えている HTML と、実際に編集すべきファイルが一致しない**
ページが多い。文言は `content.js`、翻訳は `translations.js`、一覧は JSON、記事は markdown。生成された HTML を直接編集すると
次の `node build.js` で消える。この対応表を毎回思い出す必要があった。

webpin はこの2つをまとめて解決する。**ブラウザで直したい箇所をクリックして指示すると、
それが「ソースのどの行か」まで解決された状態で記録される。**

## できること

ローカルサーバーを立て、配信する HTML にオーバーレイ UI を自動で差し込む。
画面右下のツールバーから4つのモードを使う。

| モード | 動作 |
|---|---|
| 注釈 | 要素をクリックしてコメントを残す。番号ピンがその場に付く |
| 文字 | クリックした文字をその場で書き換える。**ソースまで自動で反映される** |
| 範囲 | ドラッグで矩形を囲み、その範囲のスクリーンショットとコメントを残す |
| 見た目 | 文字サイズ・余白・色をその場で変えて、変更値を記録する（CSS への反映は AI 側） |

溜まった指摘は Claude Code の `/web-review` スキルがまとめて処理する。

## 使う場所

**汎用ツール**。ローカルのディレクトリを配信できる Web プロジェクトなら何にでも使える。
`webpin` を叩いたディレクトリから git ルートを遡って、それをプロジェクトとして扱う。

特定のサイト固有の知識はコードに入っていない。build.js の有無やファイル構成から動的に判断する。

## 置き場所

| もの | 場所 |
|---|---|
| 本体 | clone したディレクトリ（例: `~/tools/webpin/`） |
| コマンド | `~/bin/webpin`（本体へのシンボリックリンク） |
| 指摘の保存先 | `~/.cache/webpin/<プロジェクト名>-<hash>/` |
| Claude 側のスキル | `~/.claude/skills/web-review/SKILL.md` |

**プロジェクトの中には何も置かない**。リポジトリが丸ごと公開ディレクトリに
コピーされる構成だと、作業用のファイルやスクリーンショットが混ざると公開されてしまう。
